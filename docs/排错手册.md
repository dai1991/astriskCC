# asterCC 迁移测试环境部署手册

**目标**：在本地虚拟机部署一套 asterCC 最新版，用于验证从旧 UCServer（CentOS 6.9 + Asterisk 1.8.32.3 + asterCC 旧版 + MySQL 5.1）的数据迁移可行性。

**适用对象**：有 Linux 基础运维能力、能在虚拟机里装系统的技术人员。

**核心原则**：测试环境与生产完全隔离，**旧机只读、不改动、不停机**；任何导入操作都在新 VM 上进行。

- **不要用** asterCC 官网的 `asterCC-BOX-3.2.iso`：官网安装页明确说该 ISO 装的是 CentOS 6.5，等于原地踏步。

### 1.2 虚拟机配置

| 项目 | 建议值 |
|---|---|
| 虚拟化平台 | VMware Workstation / VirtualBox / KVM 均可 |
| CPU / 内存 | 4 vCPU / 8 GB（最低 2 核 4 GB，但会卡） |
| 硬盘 | ≥ 80 GB（装 Asterisk + 数据库 + Web + 录音） |
| 网络 | **桥接模式优先**（方便 IP 话机/软电话注册）；NAT 也可，但需配端口转发 |
| 快照 | 装好系统做一个、导入数据前再做一个 |

### 1.3 从旧机导出的数据（在旧机只读操作）

先在旧机确认数据库位置（前面排查发现只有 `mysql-libs`，server 包未在 RPM 清单中）：

```bash
ps aux | grep -iE 'mysqld|mariadb'
ss -tlnp | grep 3306
```

确认后导出：

```bash
# 数据库全备（MySQL 5.1 的 mysqldump 选项）
mysqldump -u root -p --all-databases > /root/astercc_backup_$(date +%F).sql

# 录音目录和 IVR 语音文件（路径需先在旧机用 find/df 确认）
find / -type d -iname '*record*' 2>/dev/null
find / -type d -iname '*ivr*' 2>/dev/null
# 找到后打包，例如：
tar czf /root/recordings.tar.gz <录音目录>
tar czf /root/ivr_prompts.tar.gz <IVR语音目录>

# 配置文件
tar czf /root/asterisk_conf.tar.gz /etc/asterisk
```

同时人工整理清单：分机号与话机型号、SIP 中继/E1 参数、IVR 流程逻辑、拨号计划要点。

把导出的 4 个文件（sql、两个 tar.gz、asterisk_conf.tar.gz）用 U 盘或 scp 传到新 VM。

## 2. 安装操作系统（推荐 CentOS 7）

> 以下安装步骤对 CentOS 7 和 Rocky 9 都适用（只在软件选择措辞上略有差异）。**推荐装 CentOS 7**，理由见第 1、4 节。

1. 新建虚拟机，挂载 DVD ISO，启动，选择 **Install CentOS Linux 7**（Rocky 9 则为 Install Rocky Linux 9）。
2. 语言选中文或英文均可；软件选择 **Minimal Install**（测试环境不需要图形界面）。
3. 网络和主机名：
   - 打开网卡开关；
   - 主机名设为 `astercc-test`；
   - 记住安装程序显示的 IP。
4. 磁盘：测试环境选自动分区即可。
5. 设置 root 密码（牢记），可另建一个普通管理员用户。
6. 开始安装 → 完成后重启 → root 登录。
7. 验证网络：

```bash
ip addr
ping -c 3 8.8.8.8
```

**关键：确认 DNS 能解析域名（实测踩坑点）**。安装脚本全程用 `wget` 从 sourceforge、asterisk.org 等境外站下载源码包；如果 DNS 用的是 8.8.8.8 等在国内解析不了的服务器，脚本会在中途下载失败并直接退出，导致 Asterisk 等关键组件**根本没装**。装完系统后务必先测域名解析：

```bash
ping -c 3 jaist.dl.sourceforge.net
ping -c 3 downloads.asterisk.org
```

若解析失败，改用国内 DNS（连接名以 `nmcli con show --active` 为准）：

```bash
nmcli con mod "ens160" ipv4.dns "223.5.5.5 114.114.114.114"
nmcli con mod "ens160" ipv4.ignore-auto-dns yes
nmcli con up "ens160"
```

## 3. 系统初始化

> **包管理器**：CentOS 7 用 `yum`，Rocky 9 用 `dnf`。下面命令以 `dnf` 为例；**CentOS 7 请把 `dnf` 全部替换成 `yum`**。

```bash
# 更新系统
dnf -y update

# 基础工具
dnf -y install wget curl vim net-tools tar

# 时间同步（呼叫中心对时间敏感，CDR 和录音都依赖）
dnf -y install chrony
systemctl enable --now chronyd
timedatectl set-timezone Asia/Shanghai

# 防火墙：二选一
# 方案 A（测试环境临时关闭，省事）：
systemctl stop firewalld && systemctl disable firewalld

# 方案 B（保留防火墙，放行必要端口；端口范围以 asterCC 实际配置为准）：
# firewall-cmd --permanent --add-service=http --add-service=https
# firewall-cmd --permanent --add-port=5060/udp --add-port=5061/tcp
# firewall-cmd --permanent --add-port=10000-20000/udp
# firewall-cmd --reload

# SELinux：测试环境可临时设为宽容模式（生产环境不建议）
setenforce 0
sed -i 's/^SELINUX=enforcing/SELINUX=permissive/' /etc/selinux/config
```

> 若计划长期保留这套测试机，防火墙和 SELinux 的建议做法是先放行、后收紧，而不是长期关闭。

## 4. 安装 asterCC

> **⚠️ 实测警告（2026-11-18，重要）**：**Rocky Linux 9 路径已被实测走不通，建议直接采用第 4B 节的 CentOS 7 方案。** 实测中 Rocky 9 上一键脚本会连续踩三个版本代差坑：① DNS/镜像域名失效（jaist.dl.sourceforge.net 已 NXDOMAIN，需 sed 替换）；② DAHDI 3.4.0 不支持 5.14 内核，编译失败；③ Asterisk 13.38.3 在 glibc 2.34 / OpenSSL 3.0 上编译失败（`menuselect.makeopts` Error 255）。尽管脚本最后打印 `Asterisk Install OK!`，但那只是无条件输出，`main/asterisk` 二进制实际不存在，`asterisk.service` 报 `203/EXEC`。**这不是补几个库能解决的，是版本代差。** 下面的 Rocky 9 步骤仅作记录，新人请直接从 **4B 节** 开始。

### 4A. Rocky Linux 9 路径（不推荐，实测失败）

```bash
cd /root
wget http://download1.astercc.org/install_asterCC_Commercial_Rocky9_php74_lastest.sh
chmod +x install_asterCC_Commercial_Rocky9_php74_lastest.sh

# 安装全程记日志，出错时便于排查
./install_asterCC_Commercial_Rocky9_php74_lastest.sh 2>&1 | tee astercc_install.log
```

**执行前须知**：

- 脚本会自动下载并安装 Asterisk、数据库、PHP 7.4、Web 服务与 asterCC 组件（**具体清单以脚本实际输出为准，本手册未取得脚本原文，不做列举**）；
- 过程视网络情况约 10–30 分钟；
- 脚本若要求输入数据库密码或其他交互，请按提示设置并**牢记**；
- 若报错：先看 `astercc_install.log` 的具体失败行，不要盲目重跑整个脚本。常见的 repo / GPG key 问题按报错提示处理即可。

**安装后检查**（用通用命令确认各组件在跑，不依赖硬编码路径）：

```bash
systemctl status asterisk
systemctl status mysqld    || systemctl status mariadb
systemctl status nginx     || systemctl status httpd
ss -tlnp | grep -E ':80|:443|:5060|:5061|:3306'
asterisk -rx 'core show version'
```

### 4B. CentOS 7 路径（推荐，脚本原生环境）

这是 asterCC 一键脚本的原生支持环境（内核 3.10 / glibc 2.17），Asterisk 13 + DAHDI 3.4 都是为它编译的，能避开 Rocky 9 上的全部版本代差问题。虽然 CentOS 7 本身已 EOL，但用作**隔离的测试环境**验证数据迁移完全够用。

**① 准备镜像与虚拟机**

- 镜像：`CentOS-7-x86_64-DVD.iso`，从 vault.centos.org 或清华/阿里等镜像站的 centos/7/isos/x86_64 下载；
- VM 配置同 1.2 节（4 核 8G 80G，桥接网卡），装系统时选 **Minimal Install**，网络和主机名照第 2 节设置。

**② 换 yum 源（必做，否则脚本第一步就失败）**

CentOS 7 已于 2024-06-30 EOL，默认 yum 源（`mirrorlist.centos.org`）已失效，必须先换成归档源：

```bash
mkdir -p /etc/yum.repos.d/bak
mv /etc/yum.repos.d/CentOS-*.repo /etc/yum.repos.d/bak/

cat > /etc/yum.repos.d/CentOS-Base.repo <<'EOF'
[base]
name=CentOS 7 - Base
baseurl=https://mirrors.aliyun.com/centos-vault/7.9.2009/os/x86_64/
gpgcheck=0
enabled=1

[updates]
name=CentOS 7 - Updates
baseurl=https://mirrors.aliyun.com/centos-vault/7.9.2009/updates/x86_64/
gpgcheck=0
enabled=1

[extras]
name=CentOS 7 - Extras
baseurl=https://mirrors.aliyun.com/centos-vault/7.9.2009/extras/x86_64/
gpgcheck=0
enabled=1
EOF

yum clean all && yum makecache
```

国内也可用清华源：把 `mirrors.aliyun.com/centos-vault` 换成 `mirrors.tuna.tsinghua.edu.cn/centos-vault`。跑通 `yum install -y wget` 后再继续。

**③ 系统初始化（CentOS 7 用 yum，不是 dnf）**

```bash
yum install -y wget vim net-tools
systemctl stop firewalld && systemctl disable firewalld
setenforce 0
sed -i 's/^SELINUX=enforcing/SELINUX=permissive/' /etc/selinux/config

# 验证 DNS（同第 2 节，必须能解析境外源）
nslookup downloads.asterisk.org
nslookup downloads.sourceforge.net
```

若 DNS 解析失败，按第 2 节的 nmcli 方法改成国内 DNS。

**④ 下载 CentOS 7 对应的脚本（注意不是 Rocky 那个）**

```bash
cd /root
wget http://download1.astercc.org/install_asterCC_Commercial_CentOS7_php7.sh
chmod +x install_asterCC_Commercial_CentOS7_php7.sh

# 预防性替换已失效的 jaist 镜像域名
sed -i 's#jaist\.dl\.sourceforge\.net#downloads.sourceforge.net#g' install_asterCC_Commercial_CentOS7_php7.sh
grep -n 'jaist' install_asterCC_Commercial_CentOS7_php7.sh   # 无输出=替换干净
```

**⑤ 预置 lame 包（双保险，理由见第 9 节）**

```bash
cd /usr/src
wget -O lame-3.100.tar.gz "https://downloads.sourceforge.net/project/lame/lame/3.100/lame-3.100.tar.gz"
ls -lh lame-3.100.tar.gz    # 约 1.5MB
```

**⑥ 执行安装**

```bash
cd /root && ./install_asterCC_Commercial_CentOS7_php7.sh 2>&1 | tee astercc_install_c7.log
```

- 过程中若出现镜像选择交互（1 German / 2 U.S. / 3 China），**输入 3 回车**；
- 若 `| tee` 管道导致交互无响应，`Ctrl+C` 后去掉管道重跑：`./install_asterCC_Commercial_CentOS7_php7.sh`；
- 若又在某个境外域名 `Resolving xxx... failed`，照第 9 节用 `sed -i` 替换该域名；
- **下载大包卡住（实测）**：`ps aux | grep '[w]get'` 若见 `wget http://download3.astercc.org/asterisk-1.8.32.3.tar.gz` 长时间进度不动（源慢/挂起），`Ctrl+C` 后用断点续传，别从头下：
  ```bash
  echo -e 'timeout=30\ntries=5' >> /root/.wgetrc
  cd /usr/src && wget -c http://download3.astercc.org/asterisk-1.8.32.3.tar.gz
  # 该源若仍挂，换官方源（同一 tarball）：
  wget -c --timeout=30 --tries=5 \
    https://downloads.asterisk.org/pub/telephony/asterisk/old-releases/asterisk-1.8.32.3.tar.gz \
    -O asterisk-1.8.32.3.tar.gz
  tar -tzf asterisk-1.8.32.3.tar.gz | head -3   # 能列出文件即完整
  ```
  下好后给脚本的下载行加 `-nc` 防止重跑时覆盖，再重跑脚本：
  ```bash
  sed -i 's#wget http://download3.astercc.org/asterisk-1.8.32.3.tar.gz#wget -nc http://download3.astercc.org/asterisk-1.8.32.3.tar.gz#' /root/install_asterCC_Commercial_CentOS7_php7.sh
  grep -n 'asterisk-1.8.32.3.tar.gz' /root/install_asterCC_Commercial_CentOS7_php7.sh
  cd /root && ./install_asterCC_Commercial_CentOS7_php7.sh 2>&1 | tee -a astercc_install_c7.log
  ```

**实测的两个必经交互 / 中断点（2026-11-18）**：

1. **首次运行会因内核头文件不匹配中断**：日志出现 `make *** [all] Error 2` 和 `please reboot your server and run this script again`。这是脚本装了新内核但要重启才能编译 DAHDI。照做：`reboot` → 重启后 `uname -r` 确认是新内核 → 重跑脚本。
2. **数据库客户端缺失导致密码死循环**：若出现 `mysql: command not found` / `mysqladmin: command not found` 并卡在 `please enter your mysql root passwd`（输什么都报 invalid），`Ctrl+C` 中断后手动装库：
   ```bash
   yum install -y mariadb mariadb-server
   systemctl start mariadb && systemctl enable mariadb
   mysqladmin -u root password '123456'      # 设一个密码并记住
   mysql -u root -p123456 -e "select version();"   # 验证
   ```
   再重跑脚本，到密码提示时输入刚设的密码即可通过。

3. **（离线 MySQL 路径）密码含 `!` 致 1045 死循环**：见 4B 步骤⑤前的专项说明——改纯字母数字密码即可。
4. **AMI 账号交互**：脚本走到 `please give an AMI user` 时输入 `astercc`；若接着问 AMI password，输入与 MySQL 相同的纯字母数字密码（如 `<YOUR_DB_PASS>`）。脚本会写入 `/etc/asterisk/manager.conf`。

**✅ 实测成功确认（2026-11-19）**：按下列全部步骤补齐后，**Web 后台成功登录**（`http://VM_IP/login`，系统信息页显示内核 3.10 / OS Linux / 监听 IP / Demo 授权 5 用户至 2027-01-17），`asterisk -V` 输出 `Asterisk 1.8.32.3`（与旧生产系统同版本），asterccc 6 进程 + 6 个 astcc_* 守护全部运行。脚本末尾的 `astercc Commercial installation finish!` 是半吊子收尾，需按下面补齐才算完整——不要只看脚本输出。

**验收后遗留项（可选优化）**：
- **CTI 显示「警告」**：内线正常但 CTI（AMI 连接）异常。通常是 manager.conf 的 `[astercc]` read 权限偏窄（`read = system,call,agent`）。修：
  ```bash
  sed -i 's/^read *=.*/read = all/' /etc/asterisk/manager.conf   # 全文件只有一处 read，直接全局替换，避开 [ ] 正则
  grep -i read /etc/asterisk/manager.conf                        # 确认 read = all
  asterisk -rx 'manager reload'
  pkill -f asterccc && cd /opt/asterisk/scripts/astercc && ./asterccc -d
  ```
  **注意**：某些终端/输入环境会把命令里的方括号 `[...]` 转义成 `$$...$$`，导致带 `\[astercc\]` 的 sed 匹配失效（执行无报错但没改成）。用上面不含方括号的全局替换写法可规避。改完刷新页面；**若仍是警告则忽略**——内线正常 + `manager show connected` 有 astercc 连接即代表 CTI 实际可用，警告只是 Demo 授权/状态检测的显示问题。最终验收以**打一通测试电话**为准，不看这个灯。
- 改 Web 默认密码、修时区（`timedatectl set-timezone Asia/Shanghai` 后重启 asterccc）、配 `rc.local` 开机自启（见下第 7 步）。

**⚠️ 脚本的收尾步骤被跳过，需手动补齐（实测 11-19）**：脚本虽报 install finish，但以下三件事没做完，照做才算完整：

1. **Web 目录未部署**：nginx 配置（`/usr/local/nginx/conf/nginx.conf`）root 指向 `/var/www/html/asterCC/app/webroot`，但该目录为空，页面返回 404。修复（软链源码目录）：
   ```bash
   mv /var/www/html/asterCC /var/www/html/asterCC.empty
   ln -s /usr/src/astercc-4.1 /var/www/html/asterCC
   chmod -R 777 /usr/src/astercc-4.1/app/tmp
   systemctl reload nginx
   curl -I http://127.0.0.1   # 应 200 OK
   ```
   **Web 报「连接数据库错误 500」**：asterCC 有两套独立数据库配置——守护进程用 `/etc/astercc.conf`（见下），**Web（CakePHP）用 `app/config/database.php`（小写 config，注意不是 `cake/config/config.php`，那是框架版本文件）**。默认写的是 root/空密码，与实际不符。改成 astercc 专用账号：
   ```bash
   sed -i "s/'login' => 'root'/'login' => 'astercc'/g; s/'password' => ''/'password' => 'asterccsecret'/g; s/'password' => 'astercc'/'password' => 'asterccsecret'/g" /usr/src/astercc-4.1/app/config/database.php
   grep -iE "'login'|'password'|'database'" /usr/src/astercc-4.1/app/config/database.php
   ```
   PHP 配置即时生效，刷新页面即可。另建 nginx 日志目录避免 `http-log/access.log failed` 报错：`mkdir -p /var/www/html/asterCC/http-log && chown -R asterisk:asterisk /var/www/html/asterCC/http-log && systemctl reload nginx`。
   **⚠️ 宿主机浏览器访问 VM IP 超时（`ERR_CONNECTION_TIMED_OUT`）**：若 VM 内 `curl -I http://192.168.159.130` 返回 200 但宿主机浏览器打不开，多半是 firewalld 拦截。注意安装脚本日志里的 `Firewalld is not running` 只是安装瞬间状态，VM 重启后 firewalld 会复活（`Active: active (running)`）。修复：
   ```bash
   systemctl stop firewalld && systemctl disable firewalld
   ```
   若关防火墙后仍不通，是 VMware NAT 模式宿主机访问不了 VM 的 NAT IP——改用桥接模式，或在虚拟网络编辑器里配端口转发（主机端口 → VM:80）。
2. **`astercc.conf` 未复制到 `/etc/`**：守护进程 `asterccc` 启动报 `Failed to open /etc/astercc.conf`。模板已被 install.sh 填好值（在 `/usr/src/astercc-4.1/scripts/astercc.conf`），直接复制即可：
   ```bash
   cp /usr/src/astercc-4.1/scripts/astercc.conf /etc/astercc.conf
   ```
   注意 **asterCC 应用层用的是专用数据库账号 `astercc` / `asterccsecret`（库 `astercc10`，前缀 `cc10_`），不是 root/<YOUR_DB_PASS>**（后者只是脚本提示变量）。若该账号不存在需手动建：
   ```bash
   mysql -u root -p'<YOUR_DB_PASS>' -e "
   GRANT ALL PRIVILEGES ON astercc10.* TO 'astercc'@'localhost' IDENTIFIED BY 'asterccsecret';
   GRANT ALL PRIVILEGES ON astercc10.* TO 'astercc'@'127.0.0.1' IDENTIFIED BY 'asterccsecret';
   FLUSH PRIVILEGES;"
   ```
3. **数据库表不全（只有 17 张统计表，asterccc 报 `Table 'astercc10.cc10_settings' doesn't exist`）**：源码带完整建表 SQL（325 张表），导入。MySQL 5.6 严格模式会在 BLOB/TEXT default 处报 `ERROR 1101`，前置 `SET SESSION sql_mode='';` 绕过：
   ```bash
   { echo "SET SESSION sql_mode='';"; cat /usr/src/astercc-4.1/sql/astercc10.sql; } > /tmp/astercc10_import.sql
   mysql -u astercc -p'asterccsecret' astercc10 < /tmp/astercc10_import.sql
   { echo "SET SESSION sql_mode='';"; cat /usr/src/astercc-4.1/sql/default_settings_en.sql; } > /tmp/default_settings_import.sql
   mysql -u astercc -p'asterccsecret' astercc10 < /tmp/default_settings_import.sql
   mysql -u astercc -p'asterccsecret' -e "use astercc10; show tables;" | wc -l   # 约 325 张
   ```
   **⚠️ 还要导入初始化数据，否则 Web 菜单空白**：只导表结构后登录会发现左侧菜单只有「退出登陆」——因为 `cc10_leftmenu_categories`（菜单分类）等表是空的。必须补导 `astercc_default_leftlist.sql`（菜单数据，关键）+ 权限相关 SQL：
   ```bash
   { echo "SET SESSION sql_mode='';"; cat /usr/src/astercc-4.1/sql/astercc_default_leftlist.sql; } > /tmp/leftlist.sql
   mysql -u astercc -p'asterccsecret' astercc10 < /tmp/leftlist.sql
   cd /usr/src/astercc-4.1/sql
   for f in astercc_privilegesID.sql astercc_role_privilegesID.sql astercc_search_fields.sql astercc_pbxtmplates.sql; do { echo "SET SESSION sql_mode='';"; cat "$f"; } > /tmp/imp_$f; mysql -u astercc -p'asterccsecret' astercc10 < /tmp/imp_$f 2>&1 | head -2; echo "$f done"; done
   ```
   另：**Web 初始管理员是数据库里的 `admin`（`usertype=systemadmin`），默认密码未知时用 SQL 重置**：
   ```bash
   mysql -u astercc -p'asterccsecret' -e "use astercc10; update cc10_accounts set password=md5('admin123') where username='admin';"
   # 浏览器退出后用 admin / admin123 登录，菜单才能完整显示
   ```
   （账号表字段：`username` 用户名、`usertype` 权限、`password` 密码 MD5、`extension` 分机；菜单显示依赖 leftmenu 数据 + systemadmin 权限）
4. **守护进程路径不对**：配置里全是旧标准路径 `/opt/asterisk/scripts/astercc/`，实际程序在 `/usr/src/astercc-4.1/scripts/64/`，建软链对齐（asterccc 才会过 `System file missing` 自检）：
   ```bash
   mkdir -p /opt/asterisk/scripts
   ln -sfn /usr/src/astercc-4.1/scripts/64 /opt/asterisk/scripts/astercc
   ln -sfn /usr/src/astercc-4.1 /var/www/html/astercc
   ```
5. **AMI 密码不一致**：`/etc/astercc.conf` 的 `[asterisk] secret` 必须与 `/etc/asterisk/manager.conf` 的 `[astercc] secret` 一致（本例都用 <YOUR_DB_PASS>），否则 dialer 报 `Login in failed`：
   ```bash
   sed -i 's/^secret *=.*/secret = <YOUR_DB_PASS>/' /etc/astercc.conf
   asterisk -rx 'manager reload'
   asterisk -rx 'manager show user astercc' | head -5   # secret: <Set> 即生效
   ```
6. **守护进程未启动**：以上都补齐后启动（asterccc 是多进程，正常会起 6 个）：
   ```bash
   cd /opt/asterisk/scripts/astercc
   ./asterccc -d
   for p in astcc_realtime readevents astcc_datamover astcc_dialer astcc_statistics astcc_sysevents; do [ -x "./$p" ] && ./$p -d; done
   ps aux | grep -iE 'asterccc|astcc_|readevents' | grep -v grep
   ```
   提示 `xxx is still running. Please stop first.` 是该进程已启动，非错误。全部起来后，浏览器登录 Web 后台（默认账号见官网手册）才算整套交付。
7. **开机自启**（手动启动的进程重启 VM 后会丢）：
   ```bash
   cat > /etc/rc.d/rc.local <<'EOF'
   #!/bin/bash
   sleep 10
   cd /opt/asterisk/scripts/astercc
   ./asterccc -d
   for p in astcc_realtime readevents astcc_datamover astcc_dialer astcc_statistics astcc_sysevents; do [ -x "./$p" ] && ./$p -d; done
   EOF
   chmod +x /etc/rc.d/rc.local
   ```

   **若 `mysqladmin ... password` 报 `Access denied ... (using password: NO)`**：说明 root 已经有密码了（通常是脚本前几次运行设的），不能用空密码方式改。改为跳过授权重置：
   ```bash
   systemctl stop mariadb
   mysqld_safe --skip-grant-tables --skip-networking &
   sleep 3
   mysql -u root
   ```
   在 `mysql>` 提示符执行：
   ```sql
   FLUSH PRIVILEGES;
   UPDATE mysql.user SET Password=PASSWORD('123456') WHERE User='root' AND Host='localhost';
   FLUSH PRIVILEGES;
   exit;
   ```
   然后恢复：
   ```bash
   pkill -9 mysqld
   systemctl start mariadb
   mysql -u root -p'123456' -e "select version();"   # 验证
   ```
   密码含 `!` 等特殊字符时，命令行里必须用单引号包住。也可先 `grep -niE 'mysqladmin|password' 脚本.sh | head` 查脚本里是否设了固定密码，直接用它登录更省事。

   **⚠️ 实测：密码含 `!` 会让 asterCC 脚本反复报 `ERROR 1045`**：脚本内部用裸的 `-p$mysql_passwd`（无引号），`!` 在传递中被 shell 处理，导致脚本校验失败、卡在 `invalid password,please try again` 死循环。但**数据库密码本身是对的**（手动 `mysql -u root -p'密码' -e "select 1;"` 能连）。解决办法——换成纯字母数字密码，脚本即可一次通过：
   ```bash
   mysql -u root -p'旧密码!' -e "SET PASSWORD FOR 'root'@'localhost' = PASSWORD('<YOUR_DB_PASS>'); FLUSH PRIVILEGES;"
   mysql -u root -p'<YOUR_DB_PASS>' -e "select version();"   # 验证后再重跑脚本，密码提示输 <YOUR_DB_PASS>
   ```

   **⚠️ 实测教训**：以上 `mysqld_safe --skip-grant-tables &` 方式**会引入新故障**——它以 root 启动，默认写 `/var/log/mysqld.log`，把日志路径和文件属主改掉，导致之后 `systemctl start mariadb` 失败（报 `install: cannot create regular file '/var/log/mysqld.log': Permission denied`、`[92B blob data]`）。若已发生，修复：
   ```bash
   touch /var/log/mysqld.log
   chown mysql:mysql /var/log/mysqld.log
   mkdir -p /var/log/mariadb && chown -R mysql:mysql /var/log/mariadb
   systemctl start mariadb
   ```
   **更稳妥的做法**：遇到 `Access denied` 时先 `grep -niE 'mysqladmin|password' 脚本.sh | head` 查脚本是否设了固定密码，能直接登录就别用 skip-grant-tables。 MariaDB 数据目录属主也要保持 `mysql:mysql`（`chown -R mysql:mysql /var/lib/mysql`），排查用 `journalctl -u mariadb -n 40 --no-pager` 看真实错误，勿反复重启。

**可忽略的非致命报错**：`RPM-GPG-KEY-EPEL-7 ... not an armored public key`、`epel-release-latest-7.noarch.rpm. Skipping`、`ius.repo: No such file or directory` —— 都是 CentOS 7 的 EPEL/IUS 老源下线所致，只要 remi 源（清华镜像）正常、PHP 7.4 能装上就不影响主线。

**系统时间**：装完务必同步，否则 CDR 和录音时间戳错乱：
```bash
yum install -y chrony
systemctl enable --now chronyd
timedatectl set-timezone Asia/Shanghai
chronyc -a makestep && date
```

## 9. 常见问题

| 现象 | 排查方向 |
|---|---|
| `asterisk.service` 报 `status=203/EXEC` | **实测踩坑**：脚本因下载失败中途退出，Asterisk 根本没装。用 `find / -name asterisk -type f` 确认无二进制 → 按下表排查下载失败原因 → 重跑脚本 |
| 日志末尾 `Name or service not known`（域名解析不了） | 改国内 DNS（见第 2 节）；见下方专项 |
| 日志末尾 `NXDOMAIN`（如 `jaist.dl.sourceforge.net`） | **实测踩坑**：SourceForge 日本 jaist 镜像域名失效，而脚本硬编码了它。换其他镜像：`sed -i 's#jaist\.dl\.sourceforge\.net#downloads.sourceforge.net#g' 安装脚本.sh` 后重跑。备选镜像：`nchc.dl.sourceforge.net`、`deac-ams.dl.sourceforge.net` |
| 其他境外源下载失败 | 看日志末尾的 `Resolving xxx... failed`，`nslookup` 确认后 `sed -i` 批量替换脚本里的域名，路径不变 |
| `dnf` 报 GPG key / repo 错误 | 按报错提示导入 key 或换用官方镜像源 |
| 装完访问不了 Web 后台 | `ss -tlnp` 看 80/443 是否监听；检查防火墙；看 nginx/httpd 状态 |
| 分机注册不上 | PJSIP 配置、防火墙 UDP 5060 与 RTP 端口、NAT 设置 |
| 数据导入报字符集错 | MySQL 5.1 → MariaDB 兼容性问题，先单表试导，必要时转 UTF-8 中间格式 |
| 中文乱码 | 检查数据库/表字符集统一为 utf8mb4 |

### 专项：`asterisk.service` 启动失败（status=203/EXEC）诊断三连

```bash
# 1. 看 service 里 ExecStart 指向哪个路径
systemctl cat asterisk

# 2. 找 asterisk 二进制到底在不在（没有 = 没装成功）
which asterisk
find / -name asterisk -type f 2>/dev/null

# 3. 看安装日志末尾，通常直接写着中止原因
tail -100 /root/astercc_install.log
```

若第 2 步只有 `/etc/sysconfig/asterisk`、`/etc/rc.d/init.d/asterisk` 等配置文件而无二进制，且第 3 步出现 `Name or service not known` / `dont have valid xxx tar package`，即可确诊为 DNS 导致安装中断。修复：按第 2 节设国内 DNS → 重跑安装脚本 → `which asterisk` 和 `asterisk -V` 验证。
