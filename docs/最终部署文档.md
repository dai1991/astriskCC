# asterCC 迁移测试环境 · 最终部署文档

> **版本**：2026-11-19 最终版
> **适用**：CentOS 7.x + 离线 MySQL 5.6.51 + astercc-4.1（实测一次跑通）
> **特点**：所有实测踩过的坑已内置为「预防步骤」，按顺序执行即可一次成功，无需事后补救。
> **用途**：验证旧 UCServer（CentOS 6.9 + Asterisk 1.8.32.3 + asterCC）的数据迁移可行性。
> **重要**：这套环境全栈 EOL（CentOS 7 / MySQL 5.6 / PHP 7.4 / Asterisk 1.8 均已停止维护），**仅供测试验证，严禁上线**。正式部署见 `vicibox-deploy/ViciBox12部署清单.html`。

---

## 0. 先读懂三个"必须"，避免踩坑

这三点是两天排查的核心教训，务必先接受：

1. **密码一律用纯字母数字，不要 `!` 等特殊字符**（本文档统一用 `<YOUR_DB_PASS>`）。asterCC 安装脚本内部用裸的 `-p$密码` 传参，`!` 会被 shell 处理，导致脚本反复报 `ERROR 1045` 死循环——即使密码本身是对的。
2. **一键脚本的 "Install OK / install finish" 不可信**。它会无条件打印成功，掩盖中途失败。每一步都用实测命令验证（如 `asterisk -V`），不要只看脚本输出。
3. **一键脚本只做了一半，收尾步骤全被跳过**。Web 目录、配置文件、守护进程、数据库表、菜单数据都要手工补齐——本文档第 6、7 节已全部内置。

## 2. 系统初始化（装机后第一件事，一次做对）

### 2.1 换 yum 源（必须，否则所有 yum install 失败）

CentOS 7 官方源已下线，换阿里云 vault 归档源：

```bash
mkdir -p /etc/yum.repos.d/bak
mv /etc/yum.repos.d/CentOS-*.repo /etc/yum.repos.d/bak/
cat > /etc/yum.repos.d/CentOS-Base.repo <<'EOF'
[base]
name=CentOS 7 - Base
baseurl=https://mirrors.aliyun.com/centos-vault/7.9.2009/os/x86_64/
gpgcheck=0
enabled=1
[updates]
name=CentOS 7 - Updates
baseurl=https://mirrors.aliyun.com/centos-vault/7.9.2009/updates/x86_64/
gpgcheck=0
enabled=1
[extras]
name=CentOS 7 - Extras
baseurl=https://mirrors.aliyun.com/centos-vault/7.9.2009/extras/x86_64/
gpgcheck=0
enabled=1
EOF
yum clean all && yum makecache
yum install -y wget vim net-tools perl perl-Data-Dumper libaio numactl chrony
```

> **注意 `perl-Data-Dumper` 必须装**：MySQL 初始化脚本 `mysql_install_db` 依赖它，缺了会报 `FATAL ERROR: please install the following Perl modules: Data::Dumper`。

### 2.2 关 SELinux（预防数据库权限问题）

```bash
setenforce 0
sed -i 's/^SELINUX=enforcing/SELINUX=permissive/' /etc/selinux/config
getenforce    # 应显示 Permissive
```

### 2.3 关防火墙（预防宿主机浏览器访问超时 ERR_CONNECTION_TIMED_OUT）

```bash
systemctl stop firewalld && systemctl disable firewalld
```

> **坑**：安装脚本日志里会显示 `Firewalld is not running`，但那只是安装瞬间状态。VM 重启后 firewalld 会复活，导致宿主机浏览器访问 `http://VM_IP` 超时（但 VM 内部 `curl` 返回 200）。所以这里直接 disable。

### 2.4 校时（呼叫中心 CDR 和录音依赖正确时间）

```bash
timedatectl set-timezone Asia/Shanghai
systemctl enable --now chronyd
chronyc -a makestep
date    # 确认显示 CST 且时间正确
```

### 2.5 给 wget 加超时（预防下载卡死干等）

```bash
echo -e 'timeout=30\ntries=5' >> /root/.wgetrc
```

## 3. 离线安装 MySQL 5.6.51

> 把下载好的 `MySQL-5.6.51-1.el7.x86_64.rpm-bundle.tar` 放到 `/root/`。

### 3.1 创建 mysql 用户（必须，否则 RPM 安装报 `user mysql does not exist`）

```bash
groupadd mysql 2>/dev/null
useradd -r -g mysql -s /bin/false mysql 2>/dev/null
id mysql
```

### 3.2 清理残留 + 解压 + 按序安装 4 个 RPM

```bash
systemctl stop mysqld mariadb 2>/dev/null
rpm -qa | grep -iE '^(mariadb|mysql|MySQL)' | xargs -r rpm -e --nodeps 2>/dev/null
[ -d /var/lib/mysql ] && mv /var/lib/mysql /var/lib/mysql.old.$(date +%s)

mkdir -p /root/mysql56-offline && cd /root/mysql56-offline
tar -xvf /root/MySQL-5.6.51-1.el7.x86_64.rpm-bundle.tar

# 关键：用 --nodigest --nosignature，不要用 --nogpgcheck（实测 rpm 报 unknown option）
rpm -ivh --nodeps --force --nodigest --nosignature MySQL-shared-compat-5.6.51-1.el7.x86_64.rpm
rpm -ivh --nodeps --force --nodigest --nosignature MySQL-client-5.6.51-1.el7.x86_64.rpm
rpm -ivh --nodeps --force --nodigest --nosignature MySQL-devel-5.6.51-1.el7.x86_64.rpm
rpm -ivh --nodeps --force --nodigest --nosignature MySQL-server-5.6.51-1.el7.x86_64.rpm
```

### 3.3 初始化数据目录 + 建服务文件

```bash
rm -rf /var/lib/mysql/*
mysql_install_db --user=mysql --datadir=/var/lib/mysql
chown -R mysql:mysql /var/lib/mysql

# RPM 未生成 service 文件，手写（不放 PIDFile，避免 systemd 误判 dead）
cat > /usr/lib/systemd/system/mysqld.service <<'EOF'
[Unit]
Description=MySQL Server
After=network.target
[Service]
Type=forking
User=mysql
Group=mysql
ExecStart=/usr/bin/mysqld_safe --datadir=/var/lib/mysql
ExecStop=/usr/bin/mysqladmin --user=root shutdown
Restart=on-failure
[Install]
WantedBy=multi-user.target
EOF
mkdir -p /var/run/mysqld && chown mysql:mysql /var/run/mysqld
systemctl daemon-reload
systemctl start mysqld && systemctl enable mysqld
```

> **坑**：service 文件里若写 `PIDFile=/var/run/mysqld/mysqld.pid`，而实际 pid 在 `/var/lib/mysql/主机名.pid`，会导致 `systemctl status` 显示 dead（但进程其实在跑）。所以这里不写 PIDFile。

### 3.4 验证（root 保持空密码，留给 asterCC 脚本设置）

```bash
mysql -u root -e "select version();"    # 应输出 5.6.51
```

> **不要手动设 root 密码**！asterCC 脚本的验证逻辑是"空密码登录再设置"，你若先设了密码，脚本会卡在密码死循环。

## 5. 运行 asterCC 安装脚本（两轮）

### 5.1 第一轮：装依赖 + 内核，然后重启

```bash
cd /root && ./install_asterCC_Commercial_CentOS7_php7.sh 2>&1 | tee -a astercc_install_c7.log
```

脚本会装大量依赖、内核，最后打印 `please reboot your server and run this script again`。

**照做重启**：

```bash
reboot
```

### 5.2 重启后确认环境

```bash
uname -r                                    # 应显示新内核 3.10.0-1160.119.1.el7
systemctl status mysqld --no-pager | head -3  # 数据库应还活着
mysql -u root -e "select version();"        # 5.6.51
getenforce                                   # Permissive
systemctl status firewalld --no-pager | head -3   # inactive (dead)
```

若 MySQL 没自启：`systemctl start mysqld`。

### 5.3 预下载 Asterisk 源码包（预防下载卡死）

脚本会下载 `asterisk-1.8.32.3.tar.gz`（约 29 MB），源 `download3.astercc.org` 很慢且易挂起。**提前用断点续传下好**，让脚本跳过：

```bash
cd /usr/src
wget -c http://download3.astercc.org/asterisk-1.8.32.3.tar.gz
# 若此源不通，换官方源：
# wget -c --timeout=30 --tries=5 https://downloads.asterisk.org/pub/telephony/asterisk/old-releases/asterisk-1.8.32.3.tar.gz -O asterisk-1.8.32.3.tar.gz
ls -lh asterisk-1.8.32.3.tar.gz && tar -tzf asterisk-1.8.32.3.tar.gz | head -3
```

给脚本下载行加 `-nc`（不覆盖已存在文件）：

```bash
sed -i 's#wget http://download3.astercc.org/asterisk-1.8.32.3.tar.gz#wget -nc http://download3.astercc.org/asterisk-1.8.32.3.tar.gz#' /root/install_asterCC_Commercial_CentOS7_php7.sh
grep -n 'asterisk-1.8.32.3.tar.gz' /root/install_asterCC_Commercial_CentOS7_php7.sh   # 确认有 -nc
```

> **版本说明**：CentOS 7 脚本装的是 **Asterisk 1.8.32.3**，与旧生产系统完全同版本——配置可直接拷，这是迁移验证最理想的情况。（此前记录的"目标 13.38.3"是弃用的 Rocky 9 路径，已作废。）

### 5.4 第二轮：完整安装

```bash
cd /root && ./install_asterCC_Commercial_CentOS7_php7.sh 2>&1 | tee -a astercc_install_c7.log
```

交互提示按下面填（**逐条输入，不要一次粘贴多行**）：

| 提示 | 输入 |
|---|---|
| `please enter your mysql root passwd` | `<YOUR_DB_PASS>` |
| `Please select the mirror...` (1/2/3) | `3`（China Server） |
| `please give an AMI user` | `astercc` |
| AMI password（若问） | `<YOUR_DB_PASS>` |

> **注意**：脚本第 84 行会报 `No package mysql56u-server available`——忽略，命令在就行。

### 5.5 验证 Asterisk（不要信脚本的 finish）

```bash
which asterisk && asterisk -V    # 应输出 Asterisk 1.8.32.3
systemctl status asterisk --no-pager | head -8   # active (running)
```

## 6. 补齐 asterCC 应用层（脚本全跳过了，必须手工）

> 脚本虽打印 `astercc Commercial installation finish!`，但以下 7 件事**一件都没做完**。全部照做才算完整。

### 6.1 部署 Web 目录（否则页面 404）

nginx 配置（`/usr/local/nginx/conf/nginx.conf`）root 指向 `/var/www/html/asterCC/app/webroot`，但目录为空。用软链对接源码：

```bash
mv /var/www/html/asterCC /var/www/html/asterCC.empty
ln -s /usr/src/astercc-4.1 /var/www/html/asterCC
chmod -R 777 /usr/src/astercc-4.1/app/tmp
mkdir -p /var/www/html/asterCC/http-log && chown -R asterisk:asterisk /var/www/html/asterCC/http-log
systemctl reload nginx
curl -I http://127.0.0.1    # 应 200 OK
```

### 6.2 复制守护进程配置 + 建专用数据库账号

```bash
cp /usr/src/astercc-4.1/scripts/astercc.conf /etc/astercc.conf

# asterCC 应用层用专用账号 astercc/asterccsecret（不是 root！）
mysql -u root -p'<YOUR_DB_PASS>' -e "
GRANT ALL PRIVILEGES ON astercc10.* TO 'astercc'@'localhost' IDENTIFIED BY 'asterccsecret';
GRANT ALL PRIVILEGES ON astercc10.* TO 'astercc'@'127.0.0.1' IDENTIFIED BY 'asterccsecret';
FLUSH PRIVILEGES;"
```

### 6.3 建守护进程路径软链（否则 asterccc 报 System file missing）

配置里全是旧路径 `/opt/asterisk/scripts/astercc/`，实际程序在 `/usr/src/astercc-4.1/scripts/64/`：

```bash
mkdir -p /opt/asterisk/scripts
ln -sfn /usr/src/astercc-4.1/scripts/64 /opt/asterisk/scripts/astercc
ln -sfn /usr/src/astercc-4.1 /var/www/html/astercc
```

### 6.4 补建数据库表 + 初始化数据（否则 asterccc 报缺表、Web 菜单空白）

脚本只建了 17 张统计表，核心表和初始化数据都没导。**一次性全部补齐**：

```bash
# 统一函数：前置 SET SESSION sql_mode='' 绕过 MySQL 5.6 严格模式的 BLOB/TEXT default 报错
imp() { { echo "SET SESSION sql_mode='';"; cat "$1"; } > /tmp/imp.sql; mysql -u astercc -p'asterccsecret' astercc10 < /tmp/imp.sql 2>&1 | grep -v 'Using a password'; }
cd /usr/src/astercc-4.1/sql
imp astercc10.sql              # 325 张表结构
imp default_settings_en.sql    # 默认设置
imp astercc_default_leftlist.sql  # 左侧菜单数据（关键！缺了菜单只有"退出登陆"）
for f in astercc_privilegesID.sql astercc_role_privilegesID.sql astercc_search_fields.sql astercc_pbxtmplates.sql; do imp "$f"; done

mysql -u astercc -p'asterccsecret' -e "use astercc10; show tables;" | wc -l   # 应约 325 张
```

### 6.5 对齐 AMI 密码 + 放宽读权限（否则 CTI 警告/dialer 登录失败）

```bash
# astercc.conf 的 secret 与 manager.conf 保持一致
sed -i 's/^secret *=.*/secret = <YOUR_DB_PASS>/' /etc/astercc.conf
# 全文件只有一处 read，直接全局替换（避开方括号正则）
sed -i 's/^read *=.*/read = all/' /etc/asterisk/manager.conf
asterisk -rx 'manager reload'
asterisk -rx 'manager show user astercc' | head -5   # 应显示 secret: <Set>
```

### 6.6 修 Web 数据库配置（否则页面报"连接数据库错误 500"）

Web（CakePHP）用独立的 `app/config/database.php`（小写 config），默认是 root/空密码：

```bash
sed -i "s/'login' => 'root'/'login' => 'astercc'/g; s/'password' => ''/'password' => 'asterccsecret'/g; s/'password' => 'astercc'/'password' => 'asterccsecret'/g" /usr/src/astercc-4.1/app/config/database.php
grep -nE "'login'|'password'|'database'" /usr/src/astercc-4.1/app/config/database.php   # 确认两组都是 astercc/asterccsecret/astercc10
chown -R asterisk:asterisk /etc/asterisk    # 预防 Web 点"重载"报 not writeable
```

### 6.7 启动全部守护进程

```bash
cd /opt/asterisk/scripts/astercc
./asterccc -d
for p in astcc_realtime readevents astcc_datamover astcc_dialer astcc_statistics astcc_sysevents; do [ -x "./$p" ] && ./$p -d; done
ps aux | grep -iE 'asterccc|astcc_|readevents' | grep -v grep
# 应看到 asterccc ×6 + 6 个 astcc_* 守护
```

> 提示 `xxx is still running. Please stop first.` 是进程已启动，非错误。

## 7. 首次登录 + 收尾

### 7.1 重置 Web 管理员密码

数据库初始 `admin` 账号（`usertype=systemadmin`）密码未知，重置：

```bash
mysql -u astercc -p'asterccsecret' -e "use astercc10; update cc10_accounts set password=md5('admin123') where username='admin';"
```

### 7.2 登录 Web 后台

浏览器访问 `http://VM_IP`，用 `admin` / `admin123` 登录。左侧菜单应完整显示（账户管理、**PBX 管理**、系统设置等）。分机配置在 **PBX 管理** 下。

> 若菜单空白 → 说明第 6.4 步的 `astercc_default_leftlist.sql` 没导成功，重导。

### 7.3 配开机自启（否则重启后进程全丢）

```bash
cat > /etc/rc.d/rc.local <<'EOF'
#!/bin/bash
sleep 15
systemctl start mysqld
systemctl start asterisk
systemctl start nginx
systemctl start redis
cd /opt/asterisk/scripts/astercc
./asterccc -d
for p in astcc_realtime readevents astcc_datamover astcc_dialer astcc_statistics astcc_sysevents; do [ -x "./$p" ] && ./$p -d; done
EOF
chmod +x /etc/rc.d/rc.local
```

## 附录 B：重要提醒

1. **方括号转义**：某些终端/输入环境会把命令里的 `[xxx]` 转成 `$$xxx$$`，导致带方括号正则的 sed 失效（无报错但不生效）。本文档已尽量用不含方括号的写法。执行后务必用 `grep` 验证结果。
2. **逐条执行**：不要用 `| tee` 管道执行有交互的命令；一次只粘贴一条命令，等它执行完再下一条。heredoc（`cat <<EOF`）如果被确认提示打断，会把内容拆成多行当命令执行。
3. **全栈 EOL**：这套环境只是验证工具。正式系统走 ViciBox 12（官方打包、可持续更新），见 `vicibox-deploy/ViciBox12部署清单.html`。
4. **详细排错过程**：见 `asterCC迁移测试环境部署手册.html`（记录了每个坑的诊断过程）。
